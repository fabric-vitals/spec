# Fabric Vitals — Metric definitions (v0.2)

**Status:** Fabric Vitals v0.2 (draft) — a technical proposal for discussion. Not a standard. Rulebook values not yet set.

This file defines the 45 candidate metrics (M01–M45) that feed the vitals D1–D7 ([`SPEC.md`](SPEC.md) §4) and the confidence output (CF). Where a metric is judged against a value the owner declares, the spec-sheet field is named ([`SPEC_SHEET.md`](SPEC_SHEET.md)); otherwise the reference is a Rulebook parameter ([`RULEBOOK.md`](RULEBOOK.md)).

This table gives each metric's identity and its **vendor-neutrality status**:
- **Vendor-neutral model exists:** an OpenConfig, IETF, IEEE or IBTA model carries it.
- **Partial:** a model exists for part of the metric, or the metric is optional.
- **SAI / consortium only:** available as a SAI stat or a consortium feature, with no OpenConfig/IETF model.
- **No standard:** derived by Fabric Vitals, or driver-specific.

Model abbreviations:
- OC: OpenConfig;
- SAI: SAI v1.19.0 stat, equal to the SONiC COUNTERS_DB name [1, 2];
- IEEE: 802.3 Clause 30/45 objects in the 802.3.2 YANG [3, 4];
- IB: InfiniBand PMA via sysfs [5];
- drv: Linux RDMA `hw_counters`, not standardized [6];
- UEC: Ultra Ethernet Specification (1.0.3 current [7]).

**Sampling.** No primary source establishes a required polling interval for AI fabrics. Cumulative counters are interval-invariant when differenced, while gauges miss µbursts unless sampled at sub-millisecond intervals or replaced by watermarks [8]. The resolution requirement is therefore a method (T20 in [`RULEBOOK.md`](RULEBOOK.md)), not a number.

**Where the vendor-neutral gaps sit:**
- **D3:** PFC counts and pause duration exist only in SAI, and the IEEE 802.3.2 PFC counters are deprecated [3]. Buffer watermarks exist only in SAI. RoCE NIC counters (M16–M18) are driver-specific [6].
- **D4:** queue-delay watermarks exist only in SAI, and in-band telemetry semantics are device-specific [36].
- **D2 and D7:** derived metrics with no standard definition, including routing convergence time (M45).
- **Configuration consistency (M43):** switch-side MTU, DSCP classification and ECN enablement are modelled in OpenConfig; PFC configuration is not (only an open issue exists [52]), and NIC-side configuration is driver-specific.

Closing the D3 gap needs one of three things: OpenConfig PFC and buffer models (only an open issue exists [52]); a vendor-neutral NIC counter set; or UEC management deliverables, which are "scheduled for a future release" [19].
